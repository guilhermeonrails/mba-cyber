## 🔎 Resposta do Ping

Cada bloco corresponde a **uma execução do cron** (no seu caso, a cada minuto).

---

## 📡 Linha inicial

```text
PING google.com (172.217.172.174) 56(84) bytes of data.
```

* `google.com` → hostname consultado via DNS
* `172.217.172.174` → IP resolvido
* `56(84) bytes` →

  * 56 bytes de payload ICMP
  * 84 bytes totais (incluindo headers IP + ICMP)

---

## 📶 Respostas individuais

```text
64 bytes from eze06s06-in-f14.1e100.net (172.217.172.174): icmp_seq=1 ttl=63 time=5.87 ms
```

Campos importantes:

* `64 bytes` → tamanho da resposta
* `icmp_seq=1` → número do pacote (sequência)
* `ttl=63` → *Time To Live*

  * indica quantos “saltos” ainda restavam
  * valor típico → rede estável, sem rota estranha
* `time=5.87 ms` → latência (tempo ida e volta)

👉 No seu caso:

* ~5 a 7 ms → **latência muito boa** (rede rápida / próxima geograficamente)

---

## 📊 Estatísticas finais

```text
2 packets transmitted, 2 received, 0% packet loss, time 1007ms
```

* `2 transmitted` → enviados
* `2 received` → recebidos
* `0% packet loss` → **nenhuma perda (ideal)**
* `time 1007ms` → duração total do teste (~1 segundo)

---

## 📈 RTT (latência)

```text
rtt min/avg/max/mdev = 5.872/6.761/7.650/0.889 ms
```

* `min` → menor latência
* `avg` → média
* `max` → maior latência
* `mdev` → variação (desvio médio)

👉 Interpretação:

* média ~6.7 ms → excelente
* variação <1 ms → conexão **estável**

---

## 🔁 Por que aparece duas vezes?

Porque o cron executou o comando **duas vezes** (em minutos diferentes) e você usou:

```bash
>> ping.log
```

→ isso **acumula os resultados no arquivo**
